# 9 · Frontend (MUI, Redux Toolkit, React Router)

Read this before your first frontend change. It takes about 15 minutes.

## 0. The stack, and why

| Job | Tool | Where |
|---|---|---|
| Components, styling, dark mode | **MUI v9** + Emotion | `src/app/theme.ts` |
| Date inputs | **MUI X Date Pickers** + dayjs | `src/components/form/FormDatePicker.tsx` |
| Server data (fetch, cache, refetch) | **RTK Query** on the typed `openapi-fetch` client | `src/services/baseApi.ts`, `src/features/<f>/<f>Api.ts` |
| Client state shared across components | **Redux Toolkit** slices | `src/features/<f>/<f>Slice.ts`, `src/app/store.ts` |
| Pages and URLs | **React Router v7** (lazy routes) | `src/app/router.tsx`, `src/pages/` |
| Forms and validation | **React Hook Form + Zod** | `src/components/form/` |
| Success / error toasts | **notistack** | `src/hooks/useMutationToast.ts` |

Chosen in the team's React toolset bakeoff (2026-10-03): MUI gave the most consistent design (0 raw colours, 0 copy-pasted blocks) and the most tests, and has a complete set of components for enterprise screens (tables, dialogs, date pickers).

## 1. The rules

| # | Rule | Why |
|---|---|---|
| 1 | Use an MUI component first; build your own only from MUI pieces | one look, accessible by default |
| 2 | Style with `sx` and theme tokens; never `style`, CSS files or raw colours | dark mode and rebranding work everywhere |
| 3 | App-wide look (colours, fonts, defaults) only in `src/app/theme.ts` | one place to change |
| 4 | Import per component: `import Button from '@mui/material/Button'` | fast dev server, small bundle |
| 5 | Use v9 APIs: `slotProps` / `slots`, not `InputProps`, `PaperProps`, `TransitionComponent` | v9 removed them; AI tools and old posts still suggest them |
| 6 | Server data goes through RTK Query, never `useEffect` + `fetch` + `useState` | caching, loading/error state and refetch for free |
| 7 | Reuse before you write: check `src/components/` and `src/hooks/` first | the bakeoff's only duplication was copied submit/toast code |

`npm run lint` (also in `make check` and CI) fails on rules 2, 4 and 5. See [guardrails](#8-guardrails).

## 3. Add a page

1. Create `src/pages/ThingsPage.tsx` exporting `ThingsPage`.
2. Add a route in `src/app/router.tsx`:
   ```tsx
   { path: 'things', lazy: () => import('../pages/ThingsPage').then((m) => ({ Component: m.ThingsPage })) },
   ```
3. Add a nav entry to `NAV_LINKS` in `src/components/layout/AppShell.tsx`.
4. Link with `<Button component={Link} to="/things">`. Read params with `useParams()`.

## 4. Server data with RTK Query

After `make gen`, wrap each endpoint you need. `fromApi` turns the typed client's result into what RTK Query expects, so types flow from the backend's OpenAPI.

```ts
// features/things/thingsApi.ts
export const thingsApi = baseApi.injectEndpoints({
  endpoints: (build) => ({
    getThings: build.query<Thing[], void>({
      queryFn: () => fromApi(() => api.GET('/api/things')),
      providesTags: [{ type: 'Thing', id: 'LIST' }],
    }),
    createThing: build.mutation<Thing, ThingIn>({
      queryFn: (body) => fromApi(() => api.POST('/api/things', { body })),
      invalidatesTags: [{ type: 'Thing', id: 'LIST' }],   // the list refetches itself
    }),
  }),
})
export const { useGetThingsQuery, useCreateThingMutation } = thingsApi
```

- Add the tag name (`'Thing'`) to `tagTypes` in `src/services/baseApi.ts`.
- Show the result with `<QueryState query={useGetThingsQuery()}>{(things) => …}</QueryState>`: it renders loading, error with Retry, and empty.
- Mutations: `const [createThing] = useCreateThingMutation()`, then `run(createThing(values).unwrap(), { success, error })` with `useMutationToast`.
- Need the result of a background job? Put the poll in a plain async function and call it from a mutation's `queryFn` (see `summariseNote` in `notesApi.ts`).
- Streaming (SSE) does not fit RTK Query; keep it in the component (see `ChatPanel.tsx`).

Redux slices are for **client** state only (filters, selection, wizard steps). Never copy server data into a slice.

## 5. Forms

Zod schema → `useForm` with `zodResolver` → one `Form*` input per field, inside `FormDialog` or a `Paper component="form"`.

```tsx
const schema = z.object({ title: z.string().trim().min(1, 'Title is required'), due: z.string().nullable() })
const { control, handleSubmit, formState } = useForm<Values>({ resolver: zodResolver(schema), defaultValues })

<FormDialog open={open} title="New thing" onClose={onClose} onSubmit={handleSubmit(save)} submitting={formState.isSubmitting}>
  <FormTextField control={control} name="title" label="Title" required />
  <FormSelect control={control} name="kind" label="Kind" options={KIND_OPTIONS} />
  <FormDatePicker control={control} name="due" label="Due date" disablePast />
</FormDialog>
```

- Schema in `features/<f>/<thing>Schema.ts`, so tests can import it.
- `FormDatePicker` stores an ISO date string (`YYYY-MM-DD`) or `null`.
- MUI has no form bindings. A new input type (checkbox, autocomplete) gets a `Form<Thing>.tsx` next to the others, built with `useController`. Don't wire `onChange` by hand in a feature.

## 6. Styling cheat sheet

```tsx
<Box sx={{ p: 2, mt: 1, bgcolor: 'background.paper', color: 'text.secondary', borderRadius: 2 }} />
<Stack direction={{ xs: 'column', sm: 'row' }} spacing={2} sx={{ alignItems: 'center' }} />
<Chip label="Done" color="success" />
<Button variant="contained" loading={isSubmitting}>Save</Button>
```

| Need | Write | Not |
|---|---|---|
| spacing | `p: 2`, `mt: 1` (1 = 8px) | `padding: '16px'` |
| colour | `'primary.main'`, `'text.secondary'`, `'divider'`, `color="error"` | `'#d32f2f'`, `'red'`, `rgb(...)` |
| layout | `Stack`, `Box`, `Grid` with `size={{ xs: 12, md: 6 }}` | `<div style=...>`, `Grid item xs={12}` |
| breakpoints | `{ xs: 'column', md: 'row' }` | `@media` in a CSS file |
| a new colour | palette entry in `theme.ts` (light and dark), then the token | a literal in the component |
| the same prop on every Button / TextField | `components.MuiX.defaultProps` in `theme.ts` | repeating it |
| status → colour | a `*_META` map with `ChipProps['color']` (see `noteMeta.ts`) | a colour map per component |

Defaults already in the theme: `TextField` is `size="small" fullWidth`, `Paper` is outlined, `Chip` is small, `Dialog` is `fullWidth maxWidth="sm"`, buttons are not upper-case.

## 7. Dark mode and theming

- `theme.ts` defines `colorSchemes.light` and `.dark`; MUI emits CSS variables.
- The toggle (top right) calls `useColorScheme().setMode(...)`; the choice persists in localStorage. Default: `system`.
- Check every new screen in both modes.
- Rebranding a new project = edit `theme.ts`.

## 8. Guardrails

`frontend/eslint.config.js`, on everything under `src/` except `theme.ts`:

| Lint message | Fix |
|---|---|
| `InputProps was removed in MUI v9` | `slotProps={{ input: {...} }}` |
| `inputProps was removed…` | `slotProps={{ htmlInput: {...} }}` |
| `InputLabelProps` / `FormHelperTextProps` / `SelectProps` | `slotProps={{ inputLabel / formHelperText / select }}` |
| `PaperProps` / `BackdropProps` / `MenuListProps` | `slotProps={{ paper / backdrop / list }}` |
| `TransitionComponent` / `TransitionProps` | `slots={{ transition }}` / `slotProps={{ transition }}` |
| `Grid has no item` | `<Grid size={{ xs: 12, md: 6 }}>` |
| `Use the sx prop … not style` | move it into `sx` |
| `Raw colour` | add to `theme.ts` palette, use the token |
| `'@mui/material' import is restricted` | `import X from '@mui/material/X'` |

`tsc` also rejects removed props; the lint message names the replacement.

## 9. Testing

| Test | Use |
|---|---|
| a component | `renderWithProviders(<X />)` (fresh store, real theme, snackbars) |
| a page, routing, a full flow | `renderApp('/things')` (in-memory router with the real routes) |
| a slice, schema or pure function | plain vitest |

- Both return `user` (user-event): `await user.click(...)`, `await user.type(...)`.
- Mock the network at the typed client: `vi.spyOn(api, 'GET').mockResolvedValue({ data, response: new Response() } as never)`.
- Query like a user: `getByRole('button', { name: 'Save' })`, `getByRole('dialog', { name: 'New note' })`, `findByText('Note added')` for toasts.

## 10. Bundle size

MUI is the largest dependency. Already handled:
- each page is its own lazy chunk (`router.tsx`);
- MUI core + Emotion sit in a `mui` chunk that stays cached across releases (`vite.config.ts`);
- date pickers load only with the pages that use them.

Check with `npm run build` and read the chunk sizes it prints.

## 11. Working with an AI assistant

`frontend/CLAUDE.md` holds these rules in short form; Claude Code loads it whenever it edits `frontend/`. If an assistant suggests `InputProps`, `<Grid item>`, a hex colour or `useEffect` + `fetch`, point it at that file. Lint catches the MUI ones anyway.
